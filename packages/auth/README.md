# Portable identity boundary

The application owns users, workspaces, memberships, entitlements and tracking in Postgres. Provider roles never directly grant workspace access. Apply `migrations/001_identity.sql` then `migrations/002_note_revisions.sql` to a dedicated database before enabling private web mode. No migration runs automatically.

WorkOS is the default concrete web driver. Configure `CONFNOTE_PUBLIC_DEMO=0`, `CONFNOTE_PUBLIC_BASE_URL`, `CONFNOTE_DATABASE_URL`, `WORKOS_API_KEY`, `WORKOS_CLIENT_ID`, `WORKOS_COOKIE_PASSWORD` (at least32 characters), and `WORKOS_WEBHOOK_SECRET`. Configure AuthKit passwordless email codes, Google/Apple and optional passkeys; Password authentication is rejected by the adapter. Register `/api/auth/callback` and `/api/auth/webhook`. PKCE state is encrypted and scoped to a ten-minute HttpOnly cookie; session refresh rotates the sealed cookie. Native clients discover endpoints at `/.well-known/confnote-auth`. Native access tokens are verified and matched to an active WorkOS session to establish authentication method.

`WorkOSAuthProvider` and `ClerkAuthProvider` implement the same injected-driver contract and run identical fake conformance tests. Clerk is an alternate integration seam, not a configured live identity deployment: its concrete hosted flow remains a deployment integration item. No provider account was created or contacted during tests.

Webhook events are verified before the idempotent Postgres inbox. Revocation, user deletion and membership deletion immediately remove access. New team provisioning and role assignment require an explicit application mapping; received provider admin roles cannot authorize themselves. Organization create/invite/remove methods exist on the WorkOS driver. An administration UI and full live webhook reconciliation need staging verification.

Do not log provider tokens or request bodies. The public origin comes only from validated configuration. Headers `x-user-id` and forwarding host headers never select identity. `x-workspace-id` is only a membership-checked selection.

Private web note writes also require `002_note_revisions.sql`. The web composition injects a PostgreSQL coordinator into the shared service; Cat retains its local storage/mutex. Each note or conference document holds a shared transaction lock across read/check/write. The API's numeric `mtime` is an opaque content revision on private web, while local/Cat keep their storage timestamps. Callers must echo the value they read. Content hashes reconcile a storage write observed after a failed metadata commit without storing note content in Postgres. Human edits, agent sections, actions and inbox synchronization use the same boundary. Database failures fail the request; storage and PostgreSQL are separate systems, so live Blob failure/recovery behavior still needs staging verification.
